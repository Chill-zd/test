# V2 source-bound context and delivery

This is a separate source implementation and trial directory. The first 14-call Introduction/Related Work trial and its raw responses remain historical artifacts. V2 does not rewrite that trial or silently upgrade a machine proposal to human approval. Final measured section/call counts belong to the coordinator's completed trial audit; representative coverage of eight types is not complete coverage of all 69 actual corpus sections.

## Source and context contract

The implementation follows the independently requested Sonnet response in `data/acceptance/structure_consultation_20261104/06_cross_section_context.json`, with the coordinator's explicit scope decisions. No lexical ban list or invented gold-standard threshold is added.

`context_sources.augment_inventory` returns a separate inventory. It preserves original physical source/unit identities and hashes, recognizes precise source-only formatting units, and records complete same-file scientific object envelopes, including declared `newtheorem` aliases. Mixed units retain their boundary limitation. Missing, malformed, ambiguous or incomplete reference targets are UNK; half an environment is not presented as a complete definition. Static TeX envelopes do not establish macro-expansion correctness, visual figure interpretation, mathematical truth or sufficiency of conditions.

`context.prepare_scan` is a local full-input budget/coverage preflight. `context.scan` uses the unified LLMClient/ledger and supplies every parsed body unit and heading in logical include order, without silently trimming source. Its selected source ledger is explicitly **not exhaustive**. SRC means the source directly states something, not that science has been verified. Section-summary cards are INF interpretations supported by SRC and remain pending human review. UNK describes information not supplied by the selected context, not proof that earlier paper material failed to establish it.

V2 `contextual.run` retains complete target-unit context for chunks, skips formatting/label units when selecting meaningful prose neighbors, and filters prior ledger entries by actual logical source position. Full explicit reference/enclosing objects are supplied separately and retain temporal provenance: a later referenced result cannot become prior-reader knowledge. Section synthesis collects references and preservation envelopes from all selected section units, not only the first. Full source and ordered direct unit/child-section maps remain available; an oversized complete request stops explicitly rather than truncating it.

Every reader-before/after and incoming/outgoing statement has a matching SRC/INF/UNK assertion. INF depends on actual SRC entries or literal source-span anchors, not on another interpretation masquerading as a scientific fact. A literal anchor asserts only the supplied span, never a scientific conclusion. Quotes cannot extend beyond actually supplied spans; a short prior quote does not make its whole source unit available. Function/task interpretations and scientific-preservation instructions remain pending human judgment.

Each analysis binds source-ledger and complete context-bundle JSON by path and SHA. `assert_context_fresh` and `load_bound_context` recheck those artifacts and source hashes for delivery. No stale context/registry is silently reused. Writer/reviewer transport preserves authorship, section scope, pending-human status, scientific conditions and required SRC/INF/UNK dependency closure. Repeated audit material may be deduplicated mechanically, but the full selected unit and complete section observation are retained. The coordinator rejected splitting the writer, silently shrinking source context or continuing after broken hashes; these are not permitted budget workarounds.

## Commands and API

Only `context-scan`, `analyze-v2` and explicit `repair-v2` dispatch models. The inventory, planning, staging and audit commands are local operations.

```bash
.venv/bin/polishpaper structure inventory-v2 --output-dir data/structure/context_v2/inventory
.venv/bin/polishpaper structure context-plan --paper PAPER --inventory-dir data/structure/context_v2/inventory
.venv/bin/polishpaper structure context-scan --paper PAPER --inventory-dir data/structure/context_v2/inventory --max-output-tokens 16384
.venv/bin/polishpaper structure analyze-v2 --paper PAPER --section 'EXACT/PATH' --inventory-dir data/structure/context_v2/inventory --source-ledger /absolute/path/source_ledger.json --max-output-tokens 16384 --max-batch-units 3 --max-batch-chars 12000 --max-chunk-chars 6000 --max-input-chars 1000000
```

A trusted local client factory may provide the coordinator's explicit Sonnet transport without changing project configuration. The Python API is `contextual.run(inventory, section, client, directory, ledger_path, ...)`; `max_output_tokens` belongs to the supplied client's provider configuration and participates in request-cache identity. The context ledger path is required so its exact hash can be audited. The optional retrieval setting `max_structure_packet_chars` is a positive integer; omitted, it remains 250000. A packet exceeding the budget fails explicitly, without silently dropping structured evidence.

The source runner `scripts/run_structure_expansion.py` exposes explicit plan/run and repaired-resume paths, uses the common extraction budget, records complete provider responses and prevents unreviewed replay after failed requests. Actual trial invocations and manifests are coordinator-owned runtime artifacts, not synthetic test output.

## Explicit repairs

`structure.repair.repair_attempt(failed_attempt_path, inventory_path, client, validation_details=None)` preserves the original failure and sends the complete original messages, the model's failed raw response and the deterministic validation error back to Sonnet. Optional details are exact diagnostic locations, not proposed scientific wording. It records the actual repair messages/hash separately from the inherited original source/schema cache key. It neither edits the model's raw response nor weakens a validator.

A new attempt becomes reusable only after the original validator passes. `verify_repair_chain` rechecks source, raw output, parsed/verified data, exact repair message prefixes and every failed-attempt hash link, including failed intermediate repairs. No fake verified manifest is generated for an intermediate failure. The runner's explicit `--resume-repaired` preserves failed statuses as history and resumes business processing; previously successful paid requests are reused from their original caches. A failed repair is not automatically resent. These format, quote-identity, coverage and temporal-dependency faults are engineering trial events, not formal Level 3 failures.

## Admission and human boundaries

Lexicon staging/activation is explicit and separate from observation extraction. The selected shared-only activation preserves old entries and excludes unreviewed additional single-source candidates. Source-context registry staging/publication is likewise explicit. Machine-proposed structural evidence may be delivered with warnings for review, but it does not satisfy human approval or the formal Level 3 gate.

Remaining human questions include whether SRC quotes support the proposed statement in context, whether inference/reader-state interpretations are reasonable, whether scientific conditions are complete, whether the source-specific structure is useful for the target manuscript, and whether a shared literal phrase is semantically appropriate. No code path may infer that these questions have been approved from valid JSON, quote bindings, source coverage, eight representative type cards or a published registry alone.
